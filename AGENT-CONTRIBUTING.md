# Agent & CI contributor notes

This document explains repository conventions for agent-related files and CI protection.

1) Protected files
- See `.github/protected-files.json` for the canonical list of protected agent and CI files.
- Protected files are enforced by CI (`.github/workflows/protect-agent-files.yml`) and locally by the pre-commit hook.

2) Enabling local pre-commit hooks
- The repository includes a hooks directory: `.githooks/pre-commit`.
- To enable hooks locally run:

  ```bash
  git config core.hooksPath .githooks
  ```

- After enabling, commit attempts that modify protected files will be blocked locally.

3) CI protection
- Pull requests and pushes run the `protect-agent-files` workflow which compares changed files against the protected list and fails the check if any protected path was modified.
- This protects agent files (`.github/agents`, `tools/agent-manager.js`, `scripts/spec_sync.py`, workflow configs, etc.) from accidental modification.

4) Generated artifacts
- Reports generated by agents are written to `.vscode/agent-reports/` and are intentionally untracked.

5) Restoring or updating agent/CI support files
- If you need to update any protected file intentionally, either:
  - Open a PR and request a reviewer with permission to approve changes to protected files, or
  - Temporarily disable the pre-commit hook locally (not recommended), make changes, and explain them clearly in the PR description.

6) Questions or changes
- To update the protected list, edit `.github/protected-files.json` and propose the change via PR. A maintainer will review.
